## Snapshot (2026-10-26, Block 1 B0–B6 done; rewritten in full when the block closes)

- **Project:** Abracodabra — a cozy-dark, tick-based (WeGo) roguelite that mixes farming, tower defense and plant genetics. Solo, Milan (Prague). Unity **6000.3.24f1** (since 2026-10-05; same editor as Bitbloom), URP 17.3, UI Toolkit. Repo `camelCaser69/Abracodebra-1.0`, branch `main`. **It stays a live game, developed alongside Bitbloom** (Decision log 2026-10-05).
- **Loop:** Planning (time frozen, player actions advance ticks: edit gene strands on seeds, plant) → Growth & Threat (the clock runs by itself, plants execute their genes, pest waves attack, Doris's belly empties) → **Dusk** (since B3: supper, every fruit goes to Doris, then the dusk check) → next round, or the run ends (win at dusk 5; lose when no plant lives or her belly is 0). The plant is the health bar (leaf loss, not HP).

## Code facts

All checked on disk 2026-10-05. Architecture map: `01_Core/Codebase_Map.md` (July 2026 sweep; re-verify before relying on it).

- **Layout:** `Assets/Scripts/` has A_ToolkitUI, Core, Ecosystem, Editor, Genes, Helpers, Items, Minigames, PlantSystem, ProceduralGeneration, Ticks, UI, Visual, WorldInteraction. UI Toolkit assets: 5 `.uss`, 3 `.uxml`. One assembly (Assembly-CSharp); no asmdefs of our own, no tests (the Test Framework package is installed).
- **Tick flow:** `TickManager.ActionsDriveTicks` is true in Planning (and before the game exists). `RequestActionTicks(int)` advances ticks only then. In Growth & Threat `ExecutionPhaseDriver` auto-ticks (Space pause, Tab speed, `SetPaused`). Plants tick through `PlantGrowth.OnTickUpdate` → `EnergySystem` and `PlantSequenceExecutor`.
- **Planning-tick invariant (B1, 2026-10-26, disk-verified):** `PlantGrowth`, `AnimalController`, `ReactiveBurstHandler`, `TileInteractionManager` (timed tiles), `DorisHungerSystem` and `WorldEffect` early-out in `OnTickUpdate` unless `RunState.GrowthAndThreat`. Still ticking in Planning: the player economy (`GardenerController`, `PlayerHungerSystem`), `RunManager.PhaseTickHandler`, cosmetics. `PlantGrowth.DelayedGrowthStart` flips Initializing → Growing after 0.5 s wall-clock even in Planning (no cells). Since B4 the Day's animals are destroyed when the wave ends (`WaveManager.EndCurrentWave`), so none reach Planning (the scene's `deletePreviousWaveAnimals: 0` only governs the start of a Day).
- **Day tally and auto-pauses (B5, disk-verified):** `WegoSystem.DayTally` static: `BeginDay(round)`, `NoteBite/Kill/Repel/FruitSet/PlantDied/DorisAtePlant/GroupArrived`, `EventCount`, `DaySeconds`, `EventsLine()`, `BreakdownLine()`, `Summary()`, `AutoPauseCount`, `LastPauseReason`, `OnAutoPause`. Notes are ignored outside `RunState.GrowthAndThreat`; the tally stays readable through Dusk and Planning (for the B6 ledger) until the next dawn. `GameUIManager.AutoPauseBanner` (`IsVisible`, `ShownReason`). For `eval`: `DayTally.Summary()`; `AnimalController.NoteDamageSource("x")` then `TakeDamage(n)` names a kill. Fruit set is counted per fruit cell, so it dominates the events number (a mature starter plant sets ~2 fruit per cycle).
- **Dusk ledger and phase banner (B6, disk-verified):** `RunManager.OnDuskLedger(SupperResult, DuskVerdict)`, `AwaitingLedger`, `ContinueFromLedger()`, `ApplyVerdict` (private); `DuskRules.ledgerWaitsForContinue`. `GameUIManager.PhaseBanner` (`IsVisible`, `ShownPhase`, `ShownNow`, `StartDayVisible`) and `.DuskLedger` (`IsVisible`, `ShownDoris/Pests/Plants`); static `UIDuskLedgerController.BuildLines(SupperResult, DuskRules)`. `DayTally.LostPlants` (name + cause: species, "Doris" or empty), `BiteBreakdown()`, `KillSourceBreakdown()`, `LostPlantsBreakdown()`; `NoteDorisAtePlant(PlantGrowth plant = null)`. **Scripted runs now stop at dusk:** call `RunManager.Instance.ContinueFromLedger()` after each dusk (or set `ledgerWaitsForContinue` false). `UIPhaseBannerController.Height` (38) is the top offset other top-edge UI uses.

## Learnings

- **Edit frequency governs gene-editor design:** players edit several seeds every Planning phase, so edit speed, not model depth, is the constraint; complexity must scale with run progression.
- **The plant is the health bar.** **Visual Genome:** gene composition deterministically drives renderer parameters.
- **Idempotent derived stats; deterministic gameplay RNG** (`IDeterministicRandom`, never raw `UnityEngine.Random` in gameplay).
- **Demo-first:** features that need new infrastructure are staged; deferred items go to `Roadmap.md`, not into prose.
- **Verify on disk after an interrupted session** before redoing anything (an interrupted session once looked like lost work when all 19 files had landed).
- **Pitch and explainer voice (2026-07):** explain, don't sell; first person, Milan's voice.
- **Milan's working preferences** (markdown never .docx; green/gray over orange/brown; UI that teaches itself; iterative deepening with adversarial passes; options weighted and scored; the design law "maximum combinations from minimum complications"; exact menu paths for manual Unity steps): CLAUDE.md §3, §5 and `02_Design/Feedback_Log.md`.
